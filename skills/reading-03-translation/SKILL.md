# Reading 03 — Scientific Literature Translation (`阅读03｜文献翻译`)

This Skill solves the four core failure modes of academic literature translation in Harbor execution environments:

1. **术语稳 (Terminology Consistency)**: Extracts domain terminology, parenthetical acronyms, and `custom_glossary` overrides (`scripts/extract_terms.py` + `schemas/terminology_seed.yaml`) into a canonical `glossary.json`, then enforces uniform Chinese renderings across title, abstract, body, captions, tables, and conclusions.
2. **段落全 (Complete Reading-Order Segmentation)**: Parses multi-column/multi-page PDF, Markdown, or TXT papers into unified `document.json` (`scripts/ingest_source.py`), merges hyphenated/continuation blocks (`scripts/segment_and_protect.py`), and tracks every paragraph 1-to-1 via immutable `segment_id`s without dropping or duplicating sections, footnotes, or captions.
3. **关系准 (Semantic & Quantitative Fidelity)**: Deterministically masks equations (`__EQ_001__`), citations (`__CIT_001__`), figure/table cross-references (`__REF_001__`), and quantitative numbers/units (`__NUM_001__`) prior to translation, preserves causal/concessive connectives and negation/scope qualifiers (`not`, `never`, `without`, `only`), and restores all protected spans verbatim (`scripts/apply_translation.py`).
4. **可核验 (Deterministic QA & Honesty)**: Runs 6 programmatic checks (`scripts/verify_translation.py`) covering alignment completeness, 100% protected-token fidelity, locked-glossary consistency, negation preservation, placeholder leakage, and honest `"refused"` / `"partial"` reporting for encrypted PDFs, scanned/un-OCR'd pages, or image-only tables.

## Harbor Runtime Contract

When invoked in the Harbor evaluation environment:
- Skill directory: `/skills/weekly-skill` (or current Skill root)
- Inputs: `/input/case.json`, `/input/task.md`, plus the target `.pdf` / `.md` / `.txt` literature file(s)
- Working directory: `/app/work`
- Final contract output: `/app/output/result.json` (generated by `scripts/build_translation_result.py`)

## Recommended Execution Workflow

### Mode A: Two-Stage Agent-Refined Translation (Recommended for Live Papers)

1. **Ingest, Extract Glossary, and Segment with Token Protection**:
   ```bash
   python scripts/ingest_source.py --input /input --out /app/work/ingest --case /input/case.json --crops
   python scripts/extract_terms.py --doc /app/work/ingest/papers/paper_1/document.json --case /input/case.json --out /app/work/translation/glossary.json
   python scripts/segment_and_protect.py --doc /app/work/ingest/papers/paper_1/document.json --out /app/work/translation/segments.json
   ```
   - Inspect `/app/work/ingest/papers/paper_1/document.json` (`status`, `uncertainties`). If `status == "refused"`, stop and immediately run `build_translation_result.py` to emit honest `"refused"` `/app/output/result.json`.

2. **Generate High-Fidelity Bilingual Segments JSON (`translations.json`)**:
   - Read `/app/work/translation/glossary.json` and `/app/work/translation/segments.json`.
   - Produce `/app/work/translation/translations.json` mapping each `segment_id` to fluent academic Chinese `target_text` while keeping every `__EQ_NNN__`, `__CIT_NNN__`, `__REF_NNN__`, `__NUM_NNN__` placeholder untouched and strictly following `target_zh` from `glossary.json`, plus concise `rationale` and `uncertain: true/false`.

3. **Apply Translations, Restore Protected Spans, Render Outputs & Run QA Gate**:
   ```bash
   python scripts/build_translation_result.py --input /input --work-dir /app/work --case /input/case.json --translations-json /app/work/translation/translations.json --result-out /app/output/result.json
   ```
   - Check `/app/work/translation/qa_report.json`. If `"passed": false`, inspect `violations` (e.g., dropped formula, terminology drift, missing negation) and patch `translations.json` before re-running `build_translation_result.py`.

### Mode B: Deterministic End-to-End Local / Offline Mode

For fast baseline drafting, schema verification, or automated offline tests:
```bash
python scripts/build_translation_result.py --input /input --work-dir /app/work --case /input/case.json --result-out /app/output/result.json
```

## Output Artifacts

Under `/app/work/translation/`:
- `glossary.json` — Validated against `schemas/glossary_schema.json`
- `segments.json` — Reading-order 1-to-1 source segments with protected token dictionaries
- `bilingual_doc.json` — Validated against `schemas/translation_schema.json`
- `bilingual.md` & `bilingual.html` — Side-by-side EN/ZH aligned manuscripts with locked glossary table & uncertainty callouts
- `zh_only.md` — Clean Chinese target manuscript preserving headings, formulas, citations, and tables
- `qa_report.json` — 6-check deterministic verification scorecard and `human_review_items`

Under `/app/output/`:
- `result.json` — Harbor deliverable JSON containing `status`, `metrics`, `artifacts`, `uncertainties`, and `verification`.

## Integrity & Anti-Fabrication Rules

- NEVER claim `status: "completed"` when the source PDF is encrypted (`status: "refused"`), scanned without OCR (`status: "partial"`), or contains unextracted image tables.
- NEVER silently alter numerical values, chemical formulas, reaction equations, units, citations, or negative polarity (`not` / `never` / `without`).
- Synthetic fixtures and `examples/example_result.json` exist solely for deterministic testing and format illustration; always clearly distinguish verified tool output from examples.
